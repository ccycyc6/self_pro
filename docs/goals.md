> 当前主线：**双目测距 → 人体轮廓 → 身高**
> 颜色模型分支（G3）判定为**弃用**，不再投入。

## 已弃用

| ID | 目标 | 结论 |
|---|---|---|
| **G3** | 颜色选择性检测 | 训练能做到（浮点 0.36 px），但**板端效果不理想**：小目标/远距离下不可靠，且引入 RGB 通道后整条链路复杂度上升。**弃用，回到 luma。** |

## 进行中 / 计划（这一阶段的主线）

| ID | 目标 | 关键点 | 验收 |
|---|---|---|---|
| **G4** | **双目采集**（现在） | 模块是 DOUBLE-DVP：两颗 OV5640 各自独立 I2C/DVP。cmos2 单开一条 32×32 缩略图链 + `0xD000_6000` 窗口 | 两路帧计数都在涨，两幅图内容一致、水平错开 |
| **G5** | 视差 → 距离 | 只在目标 ROI 内做 SAD（8×8 块、0..31 视差），中位数抗遮挡；`Z = f·B/d` | 1/2/3 m 与卷尺误差 <15% |
| **G6** | 人体轮廓 | **白墙背景差分**（摄像头固定）：`|当前-背景| > θ` → 最大连通块 → 上下边界。**不用重训模型** | 能框住人、取到脚/头顶两行 |
| **G7** | 身高 | `身高 = Z · 像素高 / f_v`，`f_v` 由标定得到 | 与卷尺误差 <15 cm |
| **G8** | 体重（可选） | **测不出来**，只能 BMI 先验；上屏须写 `w~68kg (BMI 22)` | 明确标注为估计 |

## 为什么从 pre-rgb 重新开始

1. 颜色模型在板上不稳定，继续调收益低；
2. 身高检测**根本不需要神经网络**：白墙 + 背景差分 + 双目视差就够；
3. 回到 pre-rgb 后固件简单很多（无 4 通道打包、无量化 scale 对齐），
   出错面小、调试快。

## 阶段顺序与依赖

```
G4 双目采集 ──► G5 视差/距离 ──► G6 人体轮廓 ──► G7 身高 ──► G8 体重(可选)
   (位流)          (固件)           (固件)          (固件)        (固件)
```

G4 之后全部是**固件改动**，不需要重烧位流 —— 这是刻意设计的：
双目通路一次做对，后面靠上传固件迭代（每轮 5 秒）。

## 每阶段的留痕规则（不变）

- 一个 gate 一次 commit + 一个 tag；
- commit 正文写：改动 / 验证 / 回滚 / 影响；
- 位流不入库，记录 sha256；
- `make yolo` 必须 `golden diff 0` 才能开 PDS。
