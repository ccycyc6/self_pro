# 运动跟踪 + 32×32 分类器 —— 实施计划（v2）

> 目标：**运动检测框 → 跟踪 → 自动标注 → 训练分类器 → 上板识别**
> 明确不做：距离测量（不可控因素太多，已从主线移除）
> 基线：`s3h` 位流；运动检测已验证可用

---

## 一、成品是什么

```
┌──────────────────────────────────────────────┐
│                                              │
│   ┌──1──┐              ┌──2──┐               │
│   │ 框  │              │ 框  │   ← 运动跟踪框  │
│   └─────┘              └─────┘    带编号      │
│                                              │
│  TRACK 2   CLASS 1                           │
└──────────────────────────────────────────────┘
       目标数      类别编号（1=盒子 2=手 …）
```

- 框：运动检测 + 帧间关联（跟踪）
- 类别：32×32 分类器（加速器），**编号上屏、名称走串口**
- 全程不依赖距离、不依赖标定、不依赖纹理

---

## 二、“识别是什么”到底现不现实

先说结论：**粗分类现实，细分类不现实。**

| 场景 | 现实性 | 说明 |
|---|---|---|
| 2–4 个**外形差别明显**的类别（手／盒子／瓶子／无目标） | ✅ 现实，预期 **80–95%** | 必须用**这台相机**采的数据训练 |
| 5–8 类，外形有区分 | ⚠️ 勉强，需要更多数据 | 32×32 灰度信息有限 |
| 10 类以上、或细粒度（哪个牌子、哪个人） | ❌ 不现实 | 分辨率与灰度都不够 |
| 任意物体检测（YOLO 那种“框任意东西”） | ❌ 不现实 | 32×32 上做框回归泛化不了 |

**原因**：分类器只看一个 32×32 灰度块（1024 个值）。人和箱子在这个尺度上可能只差几个像素的轮廓。
所以关键不是“网络多大”，而是**你选的类别在 32×32 上是否一眼可分**。

**建议的类别设计**（选外形差异最大的）：
- 手（张开） / 盒子（方形） / 瓶子（细高） / 空（无目标）

## 三、分阶段

### M0 冻结与简化（0.5 h）

- 把测距代码从主循环移除（保留函数，不调用）；
- 主循环只做：运动检测 → 框 → 串口日志；
- 打 tag `stable-motion`。

**Gate**：`make yolo` 绿；上板挥手出框、静止无框。

### M1 运动跟踪（1 天）——**这是本次核心**

现在的运动检测是“每帧独立找连通域”，框会跳。要变成**带 ID 的跟踪**：

| 步骤 | 做法 |
|---|---|
| 检测 | 32×32 帧差 → 阈值 → 连通域（最多 4 个） |
| 关联 | 把本帧框与上一帧框按**中心距离**做最近邻匹配（阈值 8 格） |
| 平滑 | 每个 track 的中心做指数平滑（α=0.4），框尺寸取最近 3 帧中位数 |
| 生命周期 | 连续 3 帧匹配上 → 确认；连续 5 帧丢失 → 删除 |
| 输出 | 最多 4 个框 + ID + 目标数上屏；串口打印 `id,cx,cy,w,h` |

**Gate**：手在画面里移动，框跟着走且 ID 不变；手停下框不消失；离开 5 帧后消失。

### M2 采集训练数据（0.5 天）

固件加一个采集模式（串口命令 `r` 开始/停止）：

```
每个已确认的 track：
  以它为中心，从 320×240 缓冲取 32×32 块
  每个输出格取 4 个采样点求平均（约 4096 次读，0.8 ms）
  通过串口按二进制发送：1 字节 id + 1024 字节图像
```

- 传输速度：115200 下 1024 字节 ≈ 90 ms/帧 → 300 帧约 **30 秒**；
- 主机侧 `tools/ml/capture.py` 收流存成 `.npz`（含 id、时间戳）。

**采数据要点**：每个类别至少 100 帧，**改变距离/角度/光照**，避免只录一个姿势。

**Gate**：录到 300+ 帧，能可视化出 32×32 灰度图（确认不是全黑/全白）。

### M3 数据集与训练（1 天）

1. **自动分组**：对采集到的 patch 做 k-means（k=4~6），把相似的自动聚在一起；
2. **人工命名**：你只需给每个簇起个名字（1 次点击）；
3. **训练**：torch，拓扑不变（4→8→16→16→N 类），数据增强（亮度/平移 ±2 px/噪声）；
4. **导出**：`pack_weights.py` 打包成 `mt_detect_weights.h`。

**Gate**：测试集准确率 ≥ 85%（混淆矩阵看一眼，别只看总数）。

### M4 上板部署（0.5 天）

- 固件：每个 track 取 32×32 块 → 跑四层网络 → 取 argmax + 置信度；
- 屏幕：框旁显示类别编号；串口打印 `id class confidence`；
- 置信度 < 阈值时不显示类别（宁可不报）。

**Gate**：放目标 → 编号正确且稳定；拿走 → 显示“无”。

### M5 验收与文档（0.5 天）

- 录一段演示；记录每类准确率；
- 更新文档、归档位流。

## 四、工作量与风险

| 阶段 | 时间 | 风险 | 风险点 |
|---|---|---|---|
| M0 | 0.5 h | 无 | — |
| **M1** | 1 天 | **低** | 纯经典算法，运动信号强 |
| M2 | 0.5 天 | 低 | 串口带宽够用（30 秒录 300 帧） |
| M3 | 1 天 | **中** | 类别在 32×32 上是否可分——**这是唯一真正的未知** |
| M4 | 0.5 天 | 低 | 只换固件，不用位流 |
| M5 | 0.5 天 | 无 | — |
| **合计** | **约 3.5 天** | | **零位流** |

**关键优势**：M1–M5 **全部是固件 + 主机侧**，一次位流都不用烧。
加速器、相机、OSD 都是现成的。

---

## 五、如果 M3 失败怎么办（保底方案）

如果分类准确率上不去（比如只有 60%），**降级但不失败**：

1. 减到 **2 类**（“有目标 / 无目标”）——这几乎一定能到 95%+；
2. 或者放弃分类，只保留 **M1 的跟踪演示**（多目标框 + ID + 计数），
   这本身就是一个完整的“智能监控”演示，不依赖任何模型。

所以这条路**最坏情况也有一个能看的成品**——这是它比测距方案靠谱的地方。
