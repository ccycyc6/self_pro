# 视觉增强 + 运动检测 —— 实施计划

> 目标：不测距，用**画质算法 + 运动检测**做一个「怎么演示都不塌」的成品
> 基线：`s3h` 位流（sha 141344AD…），双相机 + 画中画 + OSD 已在板上验证

---

## 一、最终形态

```
┌──────────────────────────────────────┬──────────────┐
│                                      │              │
│   cam1 主画面：增强后（夜视/伪彩/锐化） │  cam2 原始灰度 │
│                                      │  （对照组）    │
│        ┌────┐        ┌────┐          │              │
│        │运动│        │运动│          │              │
│        └────┘        └────┘          │              │
└──────────────────────────────────────┴──────────────┘
         NIGHT VISION          02
         ↑ 当前模式            ↑ 运动目标数
```

**为什么这个方案稳**：增强只查表、运动检测只做帧差，**都不依赖场景里有纹理、有标定、有物体**
——现场效果 100% 可复现。

---

## 二、分阶段（每阶段一个 gate）

### P0 冻结现状（0.5 h）

- 打 tag `stable-s3h`；
- 三条验证必须绿：`make yolo`（golden 0）、`make stereo-sim`、`make pip`；
- 产物归档到 `build/release/`。

**Gate**：三条全绿。

### P1 `video_fx.v`（1 h）

像素域模块，插在 **PiP 之后、OSD 之前**，只处理主画面：

| 模式 | 算法 | 实现 |
|---|---|---|
| 0 直通 | — | 直连 |
| 1 夜视 | 伽马提升 + 绿色单色 + 噪声门限 | 256 项 LUT（R/G/B 查表） |
| 2 伪彩 | 亮度 → 蓝→青→绿→黄→红 | 256 项 24 位调色板 LUT |
| 3 锐化 | 3×3 拉普拉斯 | 需要 2 行行缓存（BRAM） |

先做 0/1/2（纯 LUT，零风险），3 作为可选加细。

**Gate**：`sim/rtl/tb_video_fx.sv` 用已知输入验证三种模式的输出（像素级对照），
`VIDEO_FX TEST PASSED`。

### P2 接入 + 位流（0.5 h + 15 min）

- `video_fb_top` 里插 `video_fx`；
- MMIO `0xD000_B000`：模式寄存器（低 2 位）；
- 构建前先跑 `tools/build_pango.ps1`（它会先 prep）。

**Gate**：位流构建通过且时序不比 s3h 差。

### P3 串口切模式（0.5 h）

- 固件轮询 UART：`n`=夜视、`f`=伪彩、`o`=原始、`s`=锐化；
- 写 MMIO 模式寄存器；
- 屏幕右下角数字显示当前模式编号。

**Gate**：串口发字符，屏幕模式立刻变化。

### P4 运动检测（2 h）

- 32×32 缩略图相邻帧相减（阈值可调）；
- 连通域 → 最多 4 个框（用现成的 4 框 OSD）；
- 屏幕文字显示目标数；
- UART `t<数字>` 调阈值，便于现场适配。

**Gate**：挥手 → 框出现；静止 → 框消失。

### P5 上板验收（0.5 h）

- 三种模式截图/录屏；
- 运动框 + 目标数；
- 记录帧率（预期运动检测只占 <0.1 M 周期 → 不受影响）。

### P6 文档与提交（0.5 h）

- 更新 `docs/advanced_plan.md` 与 `docs/goals.md`；
- 归档位流 + sha256；
- 一个 gate 一个 commit + tag。

## 三、工作量与风险

| 阶段 | 时间 | 风险 | 说明 |
|---|---|---|---|
| P0 | 0.5 h | 无 | 只是冻结 |
| P1 | 1 h | 低 | 纯查表，仿真可验证 |
| P2 | 0.5 h + 15 min | 低 | 像素域插一段，不碰 DDR3 |
| P3 | 0.5 h | 无 | 一个寄存器 |
| P4 | 2 h | 低 | 帧差是最稳的 CV 算法 |
| P5-P6 | 1 h | 无 | — |
| **合计** | **约 5.5 h + 1 次位流** | | |

**唯一的硬件代价**：一次 12 分钟位流（PDS 2025），因为 `video_fx` 在像素域。

---

## 四、和 YOLO 的关系

这条链路是 YOLO 的**前置条件**，不是替代：

```
低照度 → [video_fx 夜视/锐化] → 32×32 → 加速器（分类器）
```

真实产品也是这么做的（先增强再检测）。所以做完 P1–P4 之后，
再把加速器接成「框内是不是目标」的分类器，成功率比之前直接检测高得多。
